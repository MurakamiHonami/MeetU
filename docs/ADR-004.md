# ADR-004: N:N環状交換における移動距離を考慮した経路探索

## Status

Proposed

## Context

N:N（3〜4人での環状）交換は `CycleFinder`（`backend/src/domain/group/CycleFinder.ts`）が担う。有向グラフ上の閉路探索として実装されており、ノード＝ユーザー、辺 X→Y は「Xの譲カードがYの求カードの条件を満たす」ことを表す。

全閉路の厳密列挙は組合せ爆発するため、以下のヒューリスティックな打ち切り付き DFS になっている。

- `MAX_CYCLE = 4`（4人までの輪）
- `MIN_CYCLE = 3`（2人交換は通常の1対1マッチが扱うため対象外）
- `MAX_BRANCH = 5`（1ノードから辿る辺の上限）
- `MAX_VISITS = 300`（探索全体の打ち切り）
- `MAX_RESULTS = 5`（1回の登録で提案する輪の数）

現状の枝選定（`outgoing()`）は **タグ一致数の多い順** に上位 `MAX_BRANCH` 件を採用し、発見したサイクル群は **サイクルの短さ** でソートして採用している。**移動距離は経路探索に一切組み込まれていない**。距離計算自体は `Location.distanceKm`（ハバサイン公式）として既に存在し、1対1マッチ（`MatchingEngine.evaluate` → `Match.distanceKm`）では参考情報として使われているが、CycleFinder はこれを参照していない。

この結果、タグ条件さえ満たせば輪が成立してしまい、実際にはメンバーの居住地が離れており受け渡しの負担が大きい輪が提案されうる。N:N交換では各ステップ（fromUser → toUser）で当事者2人がその都度個別に会う想定であり、輪全体の「合計移動距離」を小さくすることが参加者の負担軽減に直結する。

また、`findCycles` が複数のサイクル候補を返し、`CardUseCase.runCycleFinding` がそれぞれを独立した `TradeGroup` として作成する現行実装では、**同一の GIVE カードが複数の輪候補に同時に登場しうる**。これは、あるユーザーが輪Aへの招待を承諾し、別のユーザーが輪B（Aと同じカードを含む）を承諾する、といった「すれ違い」を招く。距離最適化の導入と合わせて、カード単位での排他性も確保する必要がある。

### 計算複雑性の検討（先行研究の調査）

「N:N交換全体で移動距離が最小になるようマッチングを最適化する」問題は、腎臓交換（Kidney Exchange）分野で長年研究されてきた **バーター交換クリアリング問題（Barter Exchange Clearing Problem）** と同型である（[Abraham, Blum, Sandholm, "Clearing Algorithms for Barter Exchange Markets: Enabling Nationwide Kidney Exchanges", EC'07](./references/abraham-blum-sandholm-2007-clearing-algorithms-barter-exchange.pdf)）。市場を有向グラフ（頂点＝エージェント、辺の重み＝交換の効用）としてモデル化し、「重みの合計が最大になる、互いに素なサイクルの集合（サイクルカバー）」を求める問題として定式化されている。

この論文の Theorem 1 が示す重要な事実:

> サイクル長を **L ≥ 3** に制限した場合、完全サイクルカバー問題は **NP完全**（3D-Matching からの多項式時間帰着で証明）。

一方で、サイクル長に関する制約の有無によって計算量が劇的に変わる。

| サイクル長の制約 | 対応する問題 | 計算量 |
|---|---|---|
| 無制限 | 二部グラフの最大重み完全マッチング（頂点分裂トリックで帰着） | 多項式時間（厳密解、目安 O(n³)） |
| 2 のみ（ペア交換） | 通常の最大重みマッチング（Edmonds） | 多項式時間（厳密解） |
| L ≤ 3 以上 | 制約付きサイクルカバー | **NP完全** |

MeetU の `MIN_CYCLE = 3` かつ `MAX_CYCLE = 4` は、この NP完全な領域に踏み込んでいる。これは`CycleFinder` の設計判断が誤っていたわけではなく、**この種の問題が本質的に持つ困難さ**である。

補足: 「多項式時間（目安 O(n³)）」の中身は、n人の全順列 n! を試すような全探索ではない。二部グラフの最大重み完全マッチングを解く標準的な手法（ハンガリアン法）は、**双対変数（ポテンシャル）と最短増加路**を用いて、確定済みのマッチングに未割当の頂点を1つずつ追加していく。1頂点を追加する処理が最短路探索により O(n²)、これを n 頂点ぶん繰り返すため合計で n × O(n²) = O(n³) となる。n! に対して n³ は n=10 で 3,628,800 対 1,000 程度まで差が開き、これが「サイクル長無制限なら実用的な時間で厳密解が求まる」ことの根拠になっている。

この「サイクル長無制限 or 長さ2のみなら多項式時間、それ以外は困難」という境界は EC'07 論文に限った話ではなく、サイクルカバー問題（cycle cover problem）一般に成り立つ、より基礎的な結果として知られている。[Manthey, "On Approximating Restricted Cycle Covers" (2005)](./references/manthey-2005-on-approximating-restricted-cycle-covers.pdf) は、有向グラフの制約付きサイクルカバー問題（L-DCC）について次の二分法（dichotomy）を示している。

> 制約集合 L が「L = {2}」または「L = D（サイクル長に制約なし）」のとき、L-DCC・Max-L-DCC(0,1)・Max-L-DCC はいずれも多項式時間で解ける。それ以外の L（3人以上を含み、かつ無制限でもない場合。MeetU の L = {3, 4} はこれに該当）では L-DCC は NP困難、Max-L-DCC(0,1) と Max-L-DCC は APX困難（＝多項式時間での定数近似も一般には保証しづらい）である。

同論文はさらに、サイクル長を無制限にした場合に多項式時間で解けることの根拠として、**有向グラフのサイクルカバー問題が二部グラフの最大重み完全マッチング問題への古典的な多項式時間帰着を持つこと**（Tutte の帰着、Lovász & Plummer, *Matching Theory* 第12章）を挙げている。これは「サイクル長無制限なら二部マッチングに帰着できる」という主張の一次情報にあたる。

また同論文は、L≥3 かつ無制限でない場合（MeetU の状況）に対して、有向グラフでは**近似比 8/3 の多項式時間近似アルゴリズム**が存在することも示している。これは厳密解を諦める代わりに「最適値の8/3倍以内」を多項式時間で保証する手法であり、フェーズ3で厳密解法（ILP・列生成）以外の選択肢を検討する際の候補になりうる。

論文の Table 2 は、この困難さが理論上の懸念に留まらないことも示している。実データに近い分布のシミュレーションでは、参加者 100人規模でも長さ2・3のサイクルが平均約2,760個、1,000人規模では約331万個、5,000人規模では約3.6億個に達する。**全サイクルの列挙は数百人規模でも非現実的**であり、`CycleFinder` の `MAX_BRANCH` / `MAX_VISITS` による打ち切りは、この問題の性質を踏まえれば妥当な工学的判断だったと言える。

論文が採用した厳密解法（ILP のサイクル定式化 + 列生成 + branch-and-price）は、10,000人規模の市場を数分〜十数分でクリアできるスケーラビリティを持つが、実装コストが大きい。CPLEX 等の商用ソルバーへの依存や、列生成・branch-and-price の実装自体がかなりの工数を要する。

### 「サイクル長無制限」の活用可能性の検討

サイクル長の制約を外せば多項式時間（二部マッチング）で厳密解が求まる、という性質を活かせないか検討した。

**辺の重みだけでは「サイクル長への制約」を表現できない。** マッチングの重みは辺（1対1の関係）に対して定義されるが、「その辺が結果としてどの長さの輪に組み込まれるか」は辺単独では決まらない。したがって「絶対に4人以下」のようなハード制約を、辺重みの工夫だけで無制限マッチングに埋め込むことはできない。

一方、今回の要件は「輪の人数は**なるべく**少ない方が良い」というソフトな選好であり、ハード制約ではない。ソフトな選好であれば、各辺の重みに一定の固定ペナルティ `β` を加えることで、間接的に短い輪を優先する効果を持たせられる。

```
重み(X→Y) = 満足度スコア（タグ一致度など） − α × 距離(X, Y) − β
```

輪の合計重みは通過する辺の数（＝人数）に比例して `β` の分だけ下がっていくため、他の条件が同程度であれば、辺数の少ない（人数の少ない）輪の方が総重みが高くなりやすい。ただし、これは傾向としての誘導であり、`β` の設定次第では長い輪が選ばれる可能性も残る点に留意する。

## Decision

段階的に導入する。

### フェーズ1（当面の対応）: 現行 DFS ヒューリスティックへの距離組み込み

厳密解法（ILP・列生成）は実装コストが大きく、MeetU の現状の候補プール規模（1回のカード登録に対してタグ整合する候補ユーザー数）であれば、現行の打ち切り付き DFS を維持しつつ距離を組み込む方が費用対効果が高いと判断する。

1. **距離情報の取得**: `CycleFinder` に `IUserRepository` を注入し、`User.homeLocation`（既存の `LocationProps`）から `Location` を復元してステップ間の距離をハバサイン公式で算出する（ユーザー単位でキャッシュ）。
2. **枝選定基準の変更**: `outgoing()` の選定基準を「タグ一致数優先」から **「距離が近い順」** に変更する。タグ一致は `MatchingEngine.satisfies()` によって既にハード条件（満たさなければ辺として採用されない）となっているため、それを通過した辺同士は距離のみで比較してよいと判断する。`Edge` / `TradeStep` に `distanceKm` を追加する。
3. **サイクル採用順の変更**: 発見したサイクル候補は、**サイクル内の合計距離（sum of `distanceKm`）が小さい順** にソートする。現行の「サイクルの短さ優先」は廃止する。3人の輪と4人の輪は区別せず、純粋に合計移動距離が小さいものを優先する。
4. **カード単位での排他的採用（重複防止）**: 距離合計でソート済みの候補リストを先頭から走査し、まだ使われていない GIVE カードのみで構成される候補を貪欲に採用する（使用済みカードを含む候補はスキップ）。同一カードが複数の提案輪に同時登場しないようにする。

### フェーズ2（将来の拡張候補）: 品質評価のための上界計算

現行ヒューリスティックがどの程度理論限界に近い解を出せているかを定量評価するため、**サイクル長無制限の最大重みマッチング**（頂点分裂による二部グラフ変換＋多項式時間の最大重みマッチング）を別途計算し、その目的関数値を「理論上到達しうる上界」として使う。これは最終的な提案として採用するものではなく（サイクル長制約に違反する輪を含みうるため）、評価・デバッグ用のベンチマークとして位置づける。

上界とのギャップが小さいことが確認できれば現行ヒューリスティックの継続で十分と判断でき、ギャップが大きい場合は下記フェーズ3の投資判断材料とする。

### フェーズ3（規模拡大時の再検討）: 厳密解法への移行

候補プールが数百〜数千規模に拡大し、現行ヒューリスティックの解の質が実用上問題になった場合は、論文のアプローチ（cycle formulation の ILP + 列生成）を参考に、以下のいずれかを検討する。

- サイクル長制約をハード制約からソフトペナルティ（辺重みに固定コスト `β` を付与）に緩和し、サイクル長無制限の最大重みマッチング（多項式時間）で近似的に解く。
- 本格的な ILP ソルバー（OSS: HiGHS、OR-Tools 等）を用いた列生成ベースの厳密解法を実装する。

## Consequences

### Positive

- （フェーズ1）環状交換の受け渡し負担（合計移動距離）が最小化された輪が優先的に提案される。
- （フェーズ1）カード単位の排他性により、同時に競合する輪の提案が起きなくなり、ユーザー体験上のすれ違いが解消される。
- 距離計算・キャッシュの仕組みは既存の `Location` / `User.homeLocation` を再利用するため、新規の技術要素は不要。
- 問題の理論的性質（NP完全性）を把握した上での設計判断であるため、将来規模が拡大した際の拡張方針（フェーズ2・3）を予め用意できている。

### Negative

- `CycleFinder` が `IUserRepository` に依存するようになり、`ICardRepository` のみだった既存の依存関係が増える（DI 配線の変更が必要）。
- `homeLocation` 未設定のユーザーが輪に含まれる場合、距離計算ができない（該当ステップは距離無限大として扱い、優先度を下げる想定）。住所未設定ユーザーが多いと最適化の効果が薄れる。
- 「距離最小化」を優先することで、タグ一致数がより多い（＝交換の満足度が高い可能性がある）組み合わせが後回しになる可能性がある。実運用でユーザー満足度への影響を見て、必要なら重み付けを再検討する。
- サイクル長（3人/4人）を区別しないため、4人の輪（成立に必要な同意人数が多く、途中辞退で流れやすい）が距離の近さだけで優先されるケースがある。
- フェーズ1のヒューリスティックは厳密最適解を保証しない。候補プールの規模やタグ整合の分布によっては、理論上より良い輪が `MAX_BRANCH` / `MAX_VISITS` の打ち切りで発見されないまま終わるリスクが残る（フェーズ2の上界計算で継続的に監視する）。
